## 1. LangGraph

**有什么用：** 把 Agent 做成有状态的图：节点、边、条件路由、并行、短路。适合「审核要先级联再 RAG 再打分」这种流程，而不是单轮 chat。

**怎么用：** 用 `StateGraph` 定义 `State`，挂 `add_node` / `add_conditional_edges`，`compile` 后可加 checkpointer；HTTP 里 `ainvoke` / `astream`。本仓库已在 `app/agents/moderation`、`chat`、`detect` 等使用。

**场景：** 举报审核全链路；Chat 的 memory∥rag→worker→main；证据生成四节点流水线。

---

## 2. Supervisor–Worker（模式）

**有什么用：** 主管负责任务分解与验收，工人只干专精活，避免一个巨型 prompt 包打天下。

**怎么用：**

- 域内：LangGraph 里「路由节点 = Supervisor，classify/retrieve/judge = Worker」。
- 研发侧：Hermes Orchestrator 只建 Kanban 卡，coder/reviewer/eval-runner 去领卡。

**场景：** 「先判断是否灰区再检索」；「规则工程：拆成查法 / 改 cascade / 跑评测三张卡」。

---

## 3. Hermes Agent + Kanban

**有什么用：** 长驻 Coding/协作运行时；Kanban 用 SQLite 看板让多个 **profile（进程级 Worker）** 协作，比同进程里乱开子 Agent 更稳，可阻塞等人审。

**怎么用：** 安装 Hermes → 配模型与 MCP → 建 profile（orchestrator/coder/…）→ 用看板工具或 dashboard 建卡、领卡、`kanban_complete`；Orchestrator 按官方文档「只拆不解」。

**场景：** Pipeline：scout→implement→review→eval；Fan-out：多条样本并行抽检；改策略前 Human-in-the-loop。

**文档：** [Kanban 概览](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban)、[Kanban tutorial](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban-tutorial)。

---

## 4. MCP + FastMCP（本仓已有）

**有什么用：** Agent↔工具标准协议。一份 Server，Pi / Hermes 等都能调，不用为每个壳写插件。

**怎么用：**

- Server：`python -m app.mcp.server`（stdio），`@mcp.tool()` 注册。
- Client：在 Pi/Hermes 配置里写 `command/args/env` 指向该 Server。
- 现有工具：`rag_search_laws`、`moderate_content`、`detect_user_score`、`generate_evidence`。

**场景：** Coding Agent 要验收审核效果；治理编排要查法规；评测脚本经 Agent 调业务能力。

**入口文件：** `app/mcp/server.py`、`app/mcp/tools_*.py`；Cursor 侧示例配置见 `.cursor/mcp.json`（可照抄到 Pi/Hermes）。

---

## 5. Pi SDK（选定的 Coding 壳）

**有什么用：** 可编程跑 Coding Agent：开会话、流式输出、自定义 Tool、挂 MCP，嵌进脚本/CI/小工具。在「Claude Code vs Pi」中选定 Pi，因其具备正式 SDK，更契合二次开发（不用 Cursor SDK）。

**怎么用：**

```text
npm install @earendil-works/pi-coding-agent
```

- `createAgentSession` + `session.prompt(...)`
- `defineTool` 做 health 等薄胶水（领域能力走 MCP）
- 会话配置挂载 ShillGuard MCP Server

**文档：** [https://pi.dev/docs/latest/sdk](https://pi.dev/docs/latest/sdk)（仓库另有 `examples/sdk/`）。

**场景：** 一键「查法→moderate→出报告」；CI 里对白名单路径做规则草稿修改；SWE-bench 子集的 scaffold 宿主。

**实现旁路目录（规划）：** `demos/governance_coding_agent/`。

---

## 6. CC Switch（可选）

**有什么用：** 桌面里统一管理多家 Coding CLI 的供应商与 **MCP 配置**，不是 Agent 本身。

**怎么用：** 安装后导入 provider，在 MCP 面板挂 `shillguard`，同步到 Hermes 等。

**场景：** 多工具来回切 API/MCP、嫌手改 json 时用；本方案非必装。

**站点：** [https://ccswitch.io](https://ccswitch.io)

---

## 7. 混合 RAG（Chroma + ES BM25 + Rerank）

**有什么用：** 法规/平台规则检索：向量语义 + 关键词 BM25，RRF 融合后再精排，父子块还原上下文。

**怎么用：**

- 建索引：`python -m app.rag.indexer`
- 运行时：`retrieve()` 或 MCP `rag_search_laws`
- 生产精排：远程 rerank API（本地 FlagEmbedding 可关，尤其 MCP 子进程）

**场景：** 审核/证据要引用法条；Chat Adaptive RAG；规则工程前先检索相关条款。

**关键代码：** `app/rag/retriever.py`、`es_client.py`、`reranker.py`、`parent_child_splitter.py`。

---

## 8. 记忆：Checkpointer + 摘要 + mem0

**有什么用：**

- **Checkpointer**：图状态/对话线程持久化（LLM 工作记忆）
- **摘要**：窗口外历史压缩
- **mem0**：长期事实语义检索（pgvector）

**怎么用：** Chat 图编译时挂 Postgres checkpointer；超阈值摘要；mem0 search/add（可配合 AMG 防护）。UI 全量历史另存 `chat_messages`，与 checkpointer 分工。

**场景：** 多轮对话；用户偏好跨会话；避免把整段 UI 历史塞进模型。

**关键代码：** `app/agents/chat/graph.py`、`memory.py`、`history_store.py`。

---

## 9. RabbitMQ + Redis

**有什么用：** 审核异步削峰、可靠投递；Redis（或内存降级）存 `taskId` 状态供 Java 轮询。

**怎么用：** `publish_moderate_job` → 消费跑图 → `task_store`；拓扑与 Java `shillguard.exchange` 对齐（Topic、`ai.moderate.request` 等）。

**场景：** 举报审核耗时长，HTTP 先返回 taskId；进程重启不丢队（持久化消息）。

**文档：** `docs/RABBITMQ_MODERATION.md`；代码：`app/queue/`。

---

## 10. LangSmith

**有什么用：** LLM/Agent 调用链追踪：延迟、报错、节点输入输出，方便多 Agent 排障与评测对照。

**怎么用：** `.env` 配 API Key/项目名；`app/observability/langsmith_setup.py` 在应用启动早期调用；关键路径可用 `@traceable` 或依赖框架自动追踪。

**场景：** 灰区误判复盘；对比 cascade ON/OFF；Pi/Kanban 任务失败时看调了哪些 MCP。

---

## 11. SWE-bench Verified（公开 Benchmark）

**有什么用：** 用真实 GitHub issue 测 Coding Agent：补丁能否过仓库测试。Coding 能力金标之一。

**怎么用：** 官方/社区 runner + Docker；锁定小子集题目；固定模型与 scaffold（Pi / Hermes），记录 pass 率与版本。

**场景：** 证明「Pi/Hermes coder 真能改代码」；**不替代**审核准确率。

---

## 12. AgentBench（公开 Benchmark）

**有什么用：** 多环境（OS/DB/Web 等）测通用 Agent 交互与决策（清华 THUDM 等）。

**怎么用：** 拉取 AgentBench 仓库与依赖，选 **1～2 个环境子集** 跑通，留日志与版本；不求刷满全部环境。

**场景：** 证明编排/工具使用的综合能力；作报告背书；**不作**业务验收唯一标准。

---

## 13. 可选公开 / 运行时评测

### GAIA

- **用：** 通用多步 + 工具助手题。
- **场景：** 治理编排含「调研汇总」时再跑 validation 小样。

### τ-bench / τ²-bench

- **用：** 多轮对话 + 调 API + 守政策，强调 pass^k 稳定性。
- **场景：** 以后做「模拟运营对话触发审核」类能力时再上。

### HermesBench

- **用：** 测 Hermes **运行时配置**（含 Kanban 委托能否闭环），不是基座模型总榜。
- **场景：** 上了 Kanban 后验证「拆卡 → 工人做完 → 用户可见结束」。
- **参考：** 社区 harness 如 `verkyyi/hermesbench`（以当时文档为准）。

---

## 14. ShillGuard-AgentEval（自建，主验收）

**有什么用：** 针对本项目 MCP/审核/检测/级联/Kanban 的任务集 + **程序化 verifier**（分数带、action、工具名、法条关键词等）。

**怎么用（规划目录）：**

```text
eval/shillguard_agent_eval/
  cases/           # instruction + expected + fixtures
  verifiers/       # 程序断言
  runners/         # 调 MCP / HTTP /（可选）经 Pi/Hermes
  reports/         # pass@1、分项、轨迹 id
```

**任务分层示例：**

| ID | 测什么 |
|----|--------|
| E1 | 单 MCP 工具选对并成功 |
| E2 | 多工具编排（查法→审核） |
| E3 | LangGraph 级联/路由终态 |
| E4 | Kanban Pipeline 闭环 |
| E5 | Coding 改夹具→分数变化（可回滚） |

**场景：** 每次改 cascade/prompt/MCP 后的回归；演示与上线验收 **以本套件为准**。

---

## 串联示例：收紧「造谣」规则并验收

1. **Hermes Kanban Supervisor** 建卡：scout / implement / review / eval。  
2. **scout（Worker）** 经 **MCP** `rag_search_laws` + `moderate_content` 摸底。  
3. **coder** 用 **Pi SDK** 或 Hermes coder 改 `eval/fixtures` 或 prompt 草稿（白名单路径）。  
4. **eval-runner** 跑 **ShillGuard-AgentEval**；可选再跑 **SWE-bench** 子集证明改码能力。  
5. 全程 **LangSmith** 留迹；线上用户审核主路径仍是 **LangGraph + RabbitMQ + Java HTTP**，不被 Coding/Kanban 替换。
