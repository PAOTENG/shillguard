## 1. 系统是什么

ShillGuard（社交媒体水军智能检测与禁言系统）由三层构成：

| 层 | 路径 | 技术 | 默认端口 |
|----|------|------|----------|
| 前端 SPA | `shill-guard-frontend` | Vue3 + Vite + Pinia + Element Plus | `3000` |
| Java 微服务 | `shill-guard` | Spring Boot 3.2 / Cloud Gateway / Nacos / MyBatis-Plus | Gateway `8080`，各服务 `9001–9010` |
| Python AI | `shill-guard-ai` | FastAPI + LangGraph + RAG + MCP | `8000` |

另：前端还代理了 **政策情报 Agent**（`PolicyRadar`）到 `8001`，不在本次三个文件夹源码内。

## 2. 主链路（业务）

```
用户浏览器 :3000
    │
    ├─ /api/*、/ws/*  ──► Gateway :8080 ──► auth/user/content/agent/notify/file/admin
    │                                              │
    │                                              ├─ MySQL shill_guard
    │                                              ├─ Redis / RabbitMQ / MinIO / Nacos
    │                                              └─ RestTemplate ──► Python :8000 /ai/*
    │
    ├─ /ai/*（部分直连 :8000）──► Python：对话 / 续写 / RAG 管理 / 审核与检测
    └─ /policy-api/* ──► :8001（政策情报，外部服务）
```

### 2.1 举报审核（端到端）

1. 用户前端 `submitReport` → Java `content` 写 `content_report`  
2. 管理端 `moderateReport` → Java `agent` → `POST /ai/moderate`  
3. Python 入 RabbitMQ（或 BackgroundTasks）→ LangGraph 审核图 → Redis 存任务结果  
4. Java 轮询 `GET /ai/moderate/result/{taskId}` → `applyAction`（禁言 / 人工复核 / 无动作）  
5. 禁言发 MQ `user.mute` → `notify` 写站内信

### 2.2 恶意用户批量检测

1. 管理端 Dashboard SSE → Java `POST /api/agent/detect-users/stream`  
2. Java 聚合当日帖子/评论 → Python `/ai/detect-users-stream`  
3. 高危再调 `/ai/detect-evidence` → 写风险/禁言记录

### 2.3 对话助手

1. 前端 `streamAiSearch` / RAG 管理页 → Python `POST /ai/chat`（SSE）  
2. 不经 Java Agent（直连或 Vite `/ai` 代理）

## 4. 复查时注意的缺口

1. **申诉 Appeal**：库表/文案有「已申诉」，Java **无申诉服务模块**。  
2. **OpenFeign**：agent 依赖开启了 Feign，实际调 Python 全是 **RestTemplate**。  
3. **README（AI 仓）偏旧**：写手/审核在 README 标未实现，代码已实现。  
4. **部分社交表**（like/follow/favorite/chat）实体在 Java 中使用，`schema.sql` 可能不全。  
5. **密钥默认值**：Python `config.py` 含默认口令/Key，生产应只用 `.env`。
