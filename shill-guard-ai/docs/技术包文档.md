## 一、FastAPI

**包用途**：Python 最主流的异步 Web 框架。基于类型注解自动做请求参数校验、自动生成 Swagger 接口文档（`/docs`）。本项目用它暴露 HTTP 接口供前端/Java 侧调用。

### `FastAPI()`

**作用**：创建一个 FastAPI 应用实例，是整个 Web 服务的根对象。所有路由、中间件都挂在它上面。

```python
app = FastAPI(title="名称", version="0.1.0", description="描述")
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `title` | str | 显示在 `/docs` Swagger 页标题 |
| `version` | str | 接口版本号 |
| `description` | str | 接口描述 |
| `docs_url` | str\|None | Swagger 路径，默认 `/docs`；设 `None` 关闭 |
| `redoc_url` | str\|None | ReDoc 路径，默认 `/redoc` |

---

### `APIRouter()`

**作用**：创建一个子路由器，用于把同一模块的接口归组管理。最终通过 `include_router` 挂到主应用。避免把所有路由都写在 `main.py` 里造成混乱。

```python
router = APIRouter(prefix="/ai", tags=["chat"])
```

| 参数 | 说明 |
|---|---|
| `prefix` | 该 router 下所有路由统一加的路径前缀 |
| `tags` | Swagger 分组标签 |

---

### `app.include_router()`

**作用**：把子 `APIRouter` 注册进主应用，使其中定义的所有路由生效。相当于「把模块的接口插到主服务上」。

```python
app.include_router(router, prefix="/ai", tags=["chat"])
```

把子 router 挂到主应用，`prefix`/`tags` 可在这里覆盖 router 自身的设置。

---

### 路由装饰器

**作用**：把一个普通 Python 函数声明为 HTTP 接口处理函数。装饰器决定了接口的 HTTP 方法和路径，FastAPI 收到匹配请求时自动调用该函数。

```python
@router.get("/path")
@router.post("/path")
@router.put("/path")
@router.delete("/path")
```

| 参数 | 说明 |
|---|---|
| `path` | 路由路径，支持 `{param}` 路径参数 |
| `response_model` | 指定响应体的 Pydantic 模型，自动序列化和文档生成 |
| `status_code` | 默认响应状态码，默认 200 |
| `summary` | Swagger 中显示的接口摘要 |

---

### 参数声明符

**作用**：告诉 FastAPI 某个函数参数应该从请求的哪个位置读取。FastAPI 根据这些声明自动解析请求、做类型转换、校验合法性，并在 Swagger 文档中展示。

| 声明符 | 来源 | 示例 |
|---|---|---|
| `Body(...)` | JSON 请求体 | `data: dict = Body(...)` |
| `Form(...)` | 表单字段（multipart 或 urlencoded）| `msg: str = Form(...)` |
| `File(...)` | 上传文件 | `file: UploadFile = File(None)` |
| `Query(...)` | URL 查询参数 `?key=val` | `page: int = Query(1)` |
| `Path(...)` | URL 路径参数 `/{id}` | `id: int = Path(...)` |
| `Header(...)` | 请求头 | `token: str = Header(...)` |

`...` 表示必填，填默认值表示选填。

---

### `UploadFile`

**作用**：FastAPI 对上传文件的封装对象，提供文件名、MIME类型、异步读取等能力。配合 `File(...)` 声明符接收 multipart/form-data 上传的文件。

```python
async def upload(file: UploadFile = File(...)):
    filename = file.filename        # 原始文件名
    content_type = file.content_type # MIME 类型，如 application/pdf
    data = await file.read()        # 读取全部内容为 bytes
    await file.seek(0)              # 重置读取指针（read 后再次读取前需调用）
    await file.close()              # 关闭文件
```

---

### `StreamingResponse`

**作用**：返回一个流式 HTTP 响应。不等内容全部生成完再发送，而是每次 `yield` 一块数据就立即推送给客户端。本项目用它实现 SSE（Server-Sent Events）让 AI 逐 token 输出。

```python
from fastapi.responses import StreamingResponse

async def gen():
    yield "data: hello\n\n"
    yield "data: [DONE]\n\n"

return StreamingResponse(gen(), media_type="text/event-stream")
```

| 参数 | 说明 |
|---|---|
| `content` | 同步/异步生成器，每次 `yield` 的数据立即推给客户端 |
| `media_type` | 响应 Content-Type，SSE 用 `text/event-stream` |
| `status_code` | HTTP 状态码，默认 200 |
| `headers` | 额外响应头字典 |

---

### `CORSMiddleware`

**作用**：解决浏览器的跨域限制（CORS）。浏览器发跨域请求时会先发一个 OPTIONS 预检请求，`CORSMiddleware` 自动响应并在响应头中声明允许的来源/方法/头，浏览器才会放行正式请求。开发期通常全放开，生产按需收紧。

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],      # 允许的来源域名列表，"*" 表示全部
    allow_credentials=True,   # 是否允许携带 Cookie
    allow_methods=["*"],      # 允许的 HTTP 方法
    allow_headers=["*"],      # 允许的请求头
)
```

## 二、Pydantic / pydantic-settings

**包用途**：Python 最流行的数据验证库。`pydantic` 负责定义数据结构并自动校验类型；`pydantic-settings` 在此基础上扩展了「从环境变量/.env 文件自动读取配置」的能力。FastAPI 内部大量使用 pydantic 做请求/响应模型。

### `BaseModel`

**作用**：数据模型基类。继承它的类自动获得：类型检查（传错类型直接报错）、数据校验（长度/范围等）、序列化（转 dict/JSON）。FastAPI 用它定义请求体和响应体，并自动生成接口文档。

```python
from pydantic import BaseModel, Field

class ChatRequest(BaseModel):
    message: str = Field(..., description="用户输入")
    thread_id: str = Field("default", description="会话 ID")
```

| `Field` 参数 | 说明 |
|---|---|
| 第一个位置参数 | `...` 必填，或直接填默认值 |
| `description` | 显示在 Swagger 文档中 |
| `min_length` / `max_length` | 字符串长度校验 |
| `ge` / `le` / `gt` / `lt` | 数值大小校验（≥ ≤ > <）|
| `pattern` | 正则校验 |
| `alias` | 字段别名（JSON key 不同时用）|

**常用方法：**

```python
obj = ChatRequest(message="你好")
obj.model_dump()          # → {"message": "你好", "thread_id": "default"}
obj.model_dump_json()     # → JSON 字符串
ChatRequest.model_validate({"message": "你好"})  # 从字典构建并校验
```

---

### `BaseSettings`（pydantic-settings）

**作用**：配置管理基类。继承它的类的字段会自动从**环境变量**和 **.env 文件**中读取，不需要手动写 `os.getenv()`。适合管理 API Key、数据库地址等敏感配置，避免硬编码在代码中。

```python
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    llm_api_key: str = ""
    llm_base_url: str | None = None

    model_config = SettingsConfigDict(
        env_file=".env",           # .env 文件路径
        env_file_encoding="utf-8", # 文件编码
        extra="ignore",            # 忽略 .env 中未定义的多余字段
        case_sensitive=False,      # 环境变量名大小写不敏感（默认）
    )
```

字段名自动从同名环境变量读取：字段 `llm_api_key` 对应环境变量 `LLM_API_KEY`。

## 三、LangChain Core（langchain-core）

**包用途**：LangChain 生态的核心抽象层，定义了消息格式、工具接口、可运行对象（Runnable）等基础协议。其他包（langchain-openai、langgraph）都基于这里的类型。本项目直接使用其消息类型和 `@tool` 装饰器。

### 消息类型

**作用**：LLM 的对话本质是「消息列表」的传递，不同角色的消息用不同类型区分。LangChain 把这些封装成统一的类，所有 LLM 后端（OpenAI/DeepSeek/通义等）都接受同样的消息格式，方便切换模型。

| 类 | 含义 | 使用场景 |
|---|---|---|
| `HumanMessage(content="...")` | 用户消息 | 用户输入 |
| `AIMessage(content="...")` | 模型回复 | LLM 输出 |
| `SystemMessage(content="...")` | 系统指令 | 人设/规则 |
| `ToolMessage(content="...", tool_call_id="...")` | 工具执行结果 | ReAct 工具返回 |
| `AIMessageChunk(content="...")` | 流式 token 片段 | astream 时每个 token |

所有消息都继承 `BaseMessage`，共有属性：

```python
msg.content       # str，消息文字内容
msg.type          # str，消息类型名（"human"/"ai"/"system"/"tool"）
msg.additional_kwargs  # dict，扩展字段（如 function_call）
```

`AIMessage` 额外属性：

```python
ai_msg.tool_calls   # list，LLM 想调用的工具列表，每项含 name/args/id
```

## 四、LangChain OpenAI（langchain-openai）

**包用途**：LangChain 官方提供的 OpenAI 接入包，封装了 OpenAI Chat Completion API 和 Embedding API。凡是兼容 OpenAI 协议的服务（DeepSeek / 通义 / Moonshot 等）只需改 `base_url` 即可复用，不用换代码。

### `ChatOpenAI`

**作用**：大语言模型客户端。封装了与 LLM API 的通信，支持同步/异步/流式调用，以及绑定工具（Tool Calling）。本项目通过它调用 DeepSeek 等模型生成回复。

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="deepseek-v3",          # 模型名
    api_key="sk-xxx",             # API 密钥
    base_url="https://...",       # 兼容 OpenAI 协议的自定义地址，None 用官方
    streaming=True,               # 开启流式，astream_events 才能逐 token 推
    temperature=0.7,              # 生成随机性，0=确定性最高，2=最随机
    max_tokens=2048,              # 单次最大输出 token 数
    timeout=60,                   # 请求超时秒数
)
```

**常用方法：**

```python
# 同步调用，返回 AIMessage
response = llm.invoke([HumanMessage(content="你好")])
response.content  # → "你好！有什么能帮你的？"

# 异步调用
response = await llm.ainvoke(messages)

# 流式（同步）
for chunk in llm.stream(messages):
    print(chunk.content, end="")

# 异步流式
async for chunk in llm.astream(messages):
    print(chunk.content, end="")

# 绑定工具（ReAct 用）
llm_with_tools = llm.bind_tools([tool1, tool2])
```

### `OpenAIEmbeddings`

**作用**：文本向量化客户端。把一段文字转换为一个高维浮点数向量（如 1536 维），语义相近的文字向量距离近。RAG 建库和检索时都需要它：建库时向量化文档片段，检索时向量化用户问题，然后找距离最近的片段。

```python
from langchain_openai import OpenAIEmbeddings

embed = OpenAIEmbeddings(
    model="text-embedding-3-small",  # 默认模型
    api_key="sk-xxx",
    base_url="https://...",          # 可选，自定义地址
    dimensions=1536,                 # 向量维度（text-embedding-3-* 支持自定义）
)
```

**常用方法：**

```python
# 批量文档向量化（建库时用）
vectors = embed.embed_documents(["文本1", "文本2"])
# → [[0.12, -0.34, ...], [0.56, 0.78, ...]]

# 单条查询向量化（检索时用）
vec = embed.embed_query("用户的问题")
# → [0.09, -0.31, ...]
```

## 五、LangGraph（langgraph）

**包用途**：基于「有状态图（State Graph）」构建 AI Agent 的框架。把 Agent 的执行流程建模为节点（Node）+ 边（Edge）的图，每个节点是一个 Python 函数，节点之间通过边连接。图执行时按边的逻辑流转，支持循环（如 ReAct 的工具调用循环）和条件分支。自带多轮记忆（checkpointer）支持。

### `StateGraph`

```python
from langgraph.graph import StateGraph, END

g = StateGraph(MyState)   # 传入 TypedDict 状态类型
```

**构建图的方法：**

```python
g.add_node("节点名", 节点函数)
# 节点函数签名：def fn(state: MyState) -> dict

g.set_entry_point("节点名")
# 设置图的起始节点

g.add_edge("A", "B")
# A 执行完，无条件跳到 B

g.add_conditional_edges(
    "A",               # 来源节点
    路由函数,           # 返回字符串，决定下一个节点名
    {"tools": "tools", END: END}  # 返回值 → 目标节点 的映射
)

compiled = g.compile(checkpointer=checkpointer)
# checkpointer：持久化检查点，None 则无记忆
```

**执行图的方法：**

```python
# 同步执行，返回最终状态
result = compiled.invoke(inputs, config={"configurable": {"thread_id": "t1"}})

# 异步执行
result = await compiled.ainvoke(inputs, config=...)

# 异步流式事件（本项目用这个）
async for event in compiled.astream_events(inputs, config=..., version="v2"):
    event["event"]   # 事件类型字符串
    event["data"]    # 事件数据
    # 常见事件类型：
    # "on_chain_start"       图开始
    # "on_chat_model_stream" LLM 吐 token（最常用）
    # "on_tool_start"        工具开始执行
    # "on_tool_end"          工具执行完毕
    # "on_chain_end"         图结束
```

---

### `add_messages` reducer

**作用**：一个状态合并函数（reducer）。LangGraph 默认对状态字段做覆盖式更新，但对话历史需要「追加」而非「覆盖」。`add_messages` 绑定到 `messages` 字段后，节点每次返回新消息，LangGraph 会自动追加到历史列表末尾，而不是替换整个列表。

```python
from langgraph.graph.message import add_messages
from typing import Annotated

class MyState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]
```

节点返回 `{"messages": [new_msg]}` 时，`add_messages` 会把 `new_msg` **追加**到历史列表，而不是覆盖。这是多轮对话记忆的基础。

---

### `MemorySaver` 和 `SqliteSaver`

**作用**：checkpointer（检查点存储器），负责在每次图执行完后把完整状态（含所有历史消息）序列化保存。下次相同 `thread_id` 的请求进来时，先从 checkpointer 恢复状态，再继续执行。这是多轮对话记忆的实现机制。

```python
from langgraph.checkpoint.memory import MemorySaver
checkpointer = MemorySaver()
# 进程内存存储，重启即丢，适合开发调试

from langgraph.checkpoint.sqlite import SqliteSaver
checkpointer = SqliteSaver.from_conn_string("./data/memory.db")
# SQLite 文件持久化，重启不丢，适合生产
```

两者接口完全一致，`compile(checkpointer=...)` 绑定后，LangGraph 会在每次图执行完自动读写状态。

---

### `ToolNode`

**作用**：LangGraph 内置的工具执行节点。当 LLM 决定调用工具时，返回的 `AIMessage` 中带有 `tool_calls` 列表。`ToolNode` 自动解析这个列表，找到对应的工具函数逐个执行，把每个结果封装成 `ToolMessage` 写回状态。省去手动分发工具调用的代码。

```python
from langgraph.prebuilt import ToolNode

tool_node = ToolNode([tool1, tool2])
g.add_node("tools", tool_node)
```

预置节点，自动解析 `AIMessage.tool_calls`，逐个调用对应工具函数，把结果包成 `ToolMessage` 写回状态。省去手动调度工具的代码。

---

### `@tool` 装饰器

**作用**：把一个普通 Python 函数变成 LangChain 工具（Tool）对象。LLM 通过读取工具的名称和 docstring（描述）来决定什么时候调用它、传什么参数。docstring 写得越清晰，LLM 调用越准确。

```python
from langchain_core.tools import tool

@tool
def calculator(expression: str) -> str:
    """计算数学表达式，返回结果字符串。"""   # ← docstring 会被 LLM 读到，影响调用决策
    return str(eval(expression))
```

装饰后的函数：
- 有 `.name` 属性（函数名）
- 有 `.description` 属性（docstring）
- 有 `.args_schema`（参数 JSON Schema）
- 可直接传给 `bind_tools` 和 `ToolNode`

## 六、ChromaDB

**包用途**：轻量级本地向量数据库。专门存储和检索高维浮点向量，核心能力是「给定一个查询向量，快速找出数据库中最相似的 N 个向量」（近似最近邻搜索）。本项目用它作为 RAG 的知识库存储。优点：纯 Python、零运维、本地文件持久化，适合中小规模知识库。

### `chromadb.PersistentClient`

```python
import chromadb

client = chromadb.PersistentClient(path="./data/chroma")
# path：向量库持久化到磁盘的目录路径

# 其他客户端类型：
# chromadb.Client()          → 纯内存，重启即丢
# chromadb.HttpClient(host, port) → 连接独立部署的 Chroma 服务
```

---

### `Collection` 操作

**作用**：集合（Collection）是 ChromaDB 中存储向量的容器，相当于关系数据库的「表」。一个客户端可以有多个集合。主要操作：写入向量（`upsert`）、相似度检索（`query`）、按 ID 查询（`get`）、删除（`delete`）。

```python
# 获取或创建集合
collection = client.get_or_create_collection(
    name="kg",                          # 集合名，相当于表名
    metadata={"hnsw:space": "cosine"},  # 距离函数：cosine余弦/l2欧氏/ip内积
)

# 写入/更新向量（已存在的 id 会更新）
collection.upsert(
    ids=["doc_0", "doc_1"],             # 每条记录的唯一 ID（字符串列表）
    embeddings=[[0.1, 0.2, ...], ...],  # 向量列表，与 ids 一一对应
    documents=["文本1", "文本2"],        # 原始文本（可选，方便查看）
    metadatas=[{"source": "a.pdf"}, {}] # 元数据（可选，支持过滤查询）
)

# 相似度查询
results = collection.query(
    query_embeddings=[[0.1, 0.2, ...]],  # 查询向量（列表的列表）
    n_results=3,                          # 返回最相似的 n 条
    where={"source": "a.pdf"},            # 元数据过滤（可选）
)
# results 结构：
# {
#   "ids": [["doc_2", "doc_5", "doc_1"]],
#   "documents": [["文本...", "文本...", "文本..."]],
#   "distances": [[0.12, 0.23, 0.34]],
#   "metadatas": [[{...}, {...}, {...}]]
# }

# 其他操作
collection.get(ids=["doc_0"])         # 按 id 查询
collection.delete(ids=["doc_0"])      # 删除
collection.count()                    # 记录总数
client.delete_collection("kg")        # 删除整个集合
client.list_collections()             # 列出所有集合名
```

## 七、文档解析相关包

**模块用途**：`doc_parser.py` 的底层工具集，负责把各种格式的文件（PDF/DOCX/PPTX/XLSX/CSV/TXT）解析为纯文本字符串，供 LLM 读取。

### PyMuPDF（`import fitz`）

**包用途**：高性能 PDF/图片解析库，核心功能是从 PDF 页面提取文字块及其坐标。相比 pypdf，它保留了排版位置信息（block 坐标），可按坐标重新排序，解决多栏 PDF 乱序问题。本项目用于解析文本型 PDF。

**`fitz.open()`**：把 PDF 字节数据打开为文档对象，后续所有操作（读页数、读文字、读图片）都从这个对象发起。

**`page.get_text("blocks")`**：提取该页所有文字块，每块含坐标和文字内容，用于按位置排序后重建阅读顺序。

```python
import fitz  # pip install pymupdf

doc = fitz.open(stream=data, filetype="pdf")  # data: bytes
# stream：字节数据；filetype：文件类型提示

doc.page_count          # 总页数
page = doc[0]           # 取第0页（Page 对象）
page = doc.load_page(0) # 同上

# 提取文本块
blocks = page.get_text("blocks")
# 每个 block 是元组：(x0, y0, x1, y1, text, block_no, block_type)
# b[0],b[1]: 左上角坐标; b[2],b[3]: 右下角坐标; b[4]: 文字内容

# 直接提取页面全文
text = page.get_text("text")   # 纯文本
text = page.get_text("dict")   # 结构化字典（含字体/大小信息）

doc.close()
```

```python
para.style.name                   # 样式名，如 "Heading 1"/"Normal"
```

### python-pptx

**包用途**：读写 `.pptx` 文件的库。PPTX 同样是 ZIP+XML 格式，python-pptx 将其解析为 `Presentation`、`Slide`、`Shape` 等对象层级。本项目遍历每张幻灯片的文字框和表格提取文字内容。

**`Presentation()`**：从文件路径或字节流打开 PPT，返回演示文稿对象，是所有 PPTX 操作的入口。

```python
from pptx import Presentation
import io

prs = Presentation(io.BytesIO(data))

prs.slides                        # 幻灯片集合
prs.slide_width                   # 宽度（EMU单位，914400 EMU = 1英寸）
prs.slide_height                  # 高度

# Slide 对象
for slide in prs.slides:
    slide.shapes                  # 所有形状列表
    slide.notes_slide             # 备注页

# Shape 对象
for shape in slide.shapes:
    shape.has_text_frame          # bool，是否有文本
    shape.has_table               # bool，是否是表格
    shape.shape_type              # 枚举值（MSO_SHAPE_TYPE.TEXT_BOX 等）
    shape.name                    # 形状名称

    # 文本框
    tf = shape.text_frame
    for para in tf.paragraphs:
        for run in para.runs:
            run.text              # 文字片段

    # 表格
    for row in shape.table.rows:
        for cell in row.cells:
            cell.text
```

### openpyxl

**包用途**：读写 `.xlsx` 文件的库。提供 `Workbook`（工作簿）、`Worksheet`（工作表）、`Cell`（单元格）三层对象。特别注意：XLSX 单元格的值类型不统一（int/float/str/datetime/None），需要逐个进行 `str()` 转换。

**`load_workbook()`**：从文件路径或字节流加载工作簿。`read_only=True` 跳过样式计算，内存占用减小约60%；`data_only=True` 返回单元格计算结果值而非公式字符串。

**`ws.iter_rows(values_only=True)`**：逐行迭代工作表，`values_only=True` 直接返回单元格值元组，而不是 Cell 对象，更高效。

```python
import openpyxl
import io

wb = openpyxl.load_workbook(
    io.BytesIO(data),
    read_only=True,   # 只读模式，跳过样式计算，内存更小
    data_only=True,   # 返回计算结果值而非公式字符串
)

wb.sheetnames                     # 所有工作表名称列表
ws = wb["Sheet1"]                 # 按名称取工作表
ws = wb.active                    # 活动工作表

ws.max_row                        # 有数据的最大行号
ws.max_column                     # 有数据的最大列号
ws.dimensions                     # 数据范围，如 "A1:H100"

# 遍历行（推荐）
for row in ws.iter_rows(values_only=True):
    # row 是值元组，如 (姓名, 18, None, ...)
    for cell_value in row:
        str(cell_value) if cell_value is not None else ""

# 指定范围遍历
for row in ws.iter_rows(min_row=2, max_row=10, values_only=True):
    ...

# 读单个单元格
ws.cell(row=1, column=1).value
ws["A1"].value

wb.close()
```

### EasyOCR

**包用途**：基于深度学习的 OCR（光学字符识别）库，支持 80+ 种语言，包括简体中文。本项目用于处理扫描件 PDF：先用 pdf2image 把 PDF 每页转成图片，再用 EasyOCR 识别图片中的文字。

**`easyocr.Reader()`**：初始化 OCR 引擎，载入指定语言的模型文件（首次运行会自动下载）。同一应用内只初始化一次，耗时较长。

**`reader.readtext()`**：识别一张图片中的所有文字，返回每个识别结果的坐标、文字内容和置信度。输入图片必须是 `np.ndarray` 格式。

```python
import easyocr
import numpy as np

# 初始化（首次会下载模型，约200MB）
reader = easyocr.Reader(
    ["ch_sim", "en"],  # 语言列表，ch_sim=简体中文，en=英文
    gpu=True,          # 是否使用 GPU，需 CUDA 环境
)

# 识别图片
results = reader.readtext(
    image,             # np.ndarray（H×W×3）或 图片路径 str 或 bytes
    detail=1,          # 1=返回坐标+文字+置信度（默认），0=只返回文字列表
    paragraph=False,   # True=合并相邻文字为段落
)

# results 结构（detail=1 时）：
# [ ([[左上,右上,右下,左下]], "文字内容", 0.95), ... ]
# 坐标：[[x1,y1],[x2,y2],[x3,y3],[x4,y4]] 四角坐标（像素）

for (coords, text, confidence) in results:
    if confidence > 0.5:     # 过滤低置信度
        print(text)
```

## 八、Python 标准库（项目用到的）

### `io`

**用途**：内存中的「假文件对象」。各种库（openpyxl、python-docx 等）要求传入文件对象，但我们有的是 bytes 字符串。`io.BytesIO/StringIO` 把内容包装成文件接口，这样库就能直接读取，无需先落盘再读。

```python
import io

io.BytesIO(data)    # 把 bytes 包装成可读写的文件对象（不落盘）
io.StringIO(text)   # 把 str 包装成可读写的文件对象
# 两者都支持 .read() / .write() / .seek() / .tell()
```

### `os`

```python
import os

os.makedirs("./data/chroma", exist_ok=True)  # 递归建目录，exist_ok=True 已存在不报错
```

### `pathlib.Path`

**用途**：现代化文件路径操作，比 `os.path` 更直观。用 `/` 运算符拼接路径，内置读写文件方法。`indexer.py` 中用它逐个遍历 `sources/` 目录下的所有文件。

```python
from pathlib import Path

p = Path(__file__).parent / "sources"  # 相对当前文件的路径拼接
p.exists()          # 是否存在
p.iterdir()         # 遍历目录下所有文件/子目录

p.read_text()       # 读取为 str
```

### `functools.lru_cache`

**用途**：函数结果缓存装饰器。第一次调用时真正执行函数，后续相同参数的调用直接返回缓存结果。本项目用它确保 `get_llm()`、`_get_collection()` 等初始化函数全局只执行一次，避免重复创建客户端对象。

```python
from functools import lru_cache

@lru_cache          # 无参数：缓存所有调用结果
@lru_cache(maxsize=128)  # 最多缓存128个不同参数的结果

def get_llm():
    return ChatOpenAI(...)
# 第一次调用真正执行，后续相同参数直接返回缓存，不重复初始化
```

### `json`

**用途**：Python 对象与 JSON 字符串互转。本项目用它将流式 token 打包成 SSE 事件数据推送给前端：`json.dumps({'delta': '你'})`。`ensure_ascii=False` 是关键，否则中文会被转义为 `\uXXXX`。

```python
import json

json.dumps({"delta": "你好"}, ensure_ascii=False)
# ensure_ascii=False：中文直接输出，不转义为 \uXXXX

json.loads('{"key": "value"}')  # JSON 字符串 → dict
```

### `csv`

**用途**：Python 内置的 CSV 文件解析库，自动处理逗号分隔、引号包裹、换行转义等 CSV 格式规则。`csv.reader` 接收按行迭代的对象作为输入，因此需要先用 `io.StringIO` 把字符串包装成文件对象。

```python
csv.DictReader(f)                         # 首行为键，每行返回字典
csv.DictWriter(f, fieldnames=["a","b"])   # 按字典写入
```
