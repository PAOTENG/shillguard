## 二、完整业务流程

### 2.1 用户侧正常使用流程

```
用户注册/登录
    │
    ├─→ 浏览帖子/视频内容
    │       │
    │       ├─→ 发表评论
    │       ├─→ 点赞评论/帖子
    │       ├─→ 关注其他用户
    │       └─→ 举报恶意评论 ─────────────→ 举报入库 → 通知审核员
    │
    └─→ 收到站内通知
            ├─→ 被点赞/被评论通知
            ├─→ 禁言通知（含违规证据）
            └─→ 申诉结果通知
```

### 2.2 Agent 自动检测流程（每天0点定时触发）

```
定时任务触发（Cron: 0 0 0 * * ?）
    │
    ▼
Agent调度服务 读取 agent_task_config
    │
    ▼
创建检测批次记录（agent_detection_task）
    │
    ▼
从数据库批量读取"近期活跃用户"或"全量用户"
    │
    ▼
HTTP调用 Python Agent服务 /api/detect
    │  传入：用户ID列表 + 评论历史数据
    │
    ▼
Python Agent 执行水军群组检测算法
    │  输出：每个用户的 anomaly_score（0~1）
    │
    ▼
Python Agent 对高分用户执行 RAG分析
    │  检索知识库（平台规则/法律法规/网暴定义）
    │  结合用户评论历史 → LLM生成文本证据
    │
    ▼
返回检测结果给 Java Agent调度服务
    │
    ▼
保存检测结果（agent_detection_result）
    │
    ├─ anomaly_score < 0.6  → 标记正常，跳过
    │
    ├─ 0.6 ≤ score < 0.9   → 标记"疑似水军"
    │                         → 发送通知给审核员人工复核
    │                         → 写入 need_manual_review=1
    │
    └─ score ≥ 0.9          → 确认违规
                              → 自动执行禁言（agent_mute_record）
                              → is_auto=1, reviewer_user_id=NULL
                              → 保存证据文件到 MinIO
                              → 发送禁言通知给被禁言用户（含证据）
                              → 更新 sys_user.status=1
```

### 2.3 举报触发检测流程

```
用户提交举报（content_report）
    │
    ▼
举报服务保存举报记录，发送 RabbitMQ 消息
    │
    ▼
Agent调度服务 消费消息
    │
    ▼
对被举报用户单独触发一次 Agent检测（trigger_type=2）
    │
    ▼
（同上 2.2 流程的后半段）
```

### 2.4 人工审核流程

```
审核员登录管理后台
    │
    ▼
查看"待复核"用户列表（need_manual_review=1）
    │
    ▼
查看 Agent 生成的证据文本 + 用户评论历史
    │
    ├─ 审核员确认违规
    │       → 手动执行禁言（is_auto=0, reviewer_user_id=审核员ID）
    │       → 保存禁言记录，发送通知
    │
    └─ 审核员认为误判
            → 标记 review_result=3（误判撤销）
            → 不禁言，结束
```

### 2.5 用户申诉流程

```
被禁言用户 → 提交申诉（agent_appeal）
    │  填写申诉理由，可上传截图
    │
    ▼
系统自动将禁言时的证据快照写入 evidence_snapshot
    │
    ▼
发送通知给管理员
    │
    ▼
管理员查看申诉 + 原始证据
    │
    ├─ 申诉通过
    │       → appeal.status=2
    │       → mute_record.status=4（申诉通过已解除）
    │       → sys_user.status=0（恢复正常）
    │       → 发送申诉通过通知给用户
    │
    └─ 申诉驳回
            → appeal.status=3
            → 发送驳回通知 + 驳回原因给用户
            → 禁言继续维持
```

## 四、各微服务详细说明

### 4.1 shill-guard-gateway（网关服务）

**职责：**
- 所有请求的唯一入口，前端只与网关通信
- 路由转发到对应微服务
- 全局 JWT Token 验签（调用 Auth 服务验证）
- 白名单放行（登录/注册接口不需要 Token）
- 全局限流（Redis + Sentinel）
- 跨域 CORS 处理

**关键路由规则：**
```yaml
/api/auth/**     → shill-guard-auth
/api/user/**     → shill-guard-user
/api/content/**  → shill-guard-content
/api/report/**   → shill-guard-report
/api/agent/**    → shill-guard-agent
/api/appeal/**   → shill-guard-appeal
/api/notify/**   → shill-guard-notify
/api/file/**     → shill-guard-file
/api/admin/**    → shill-guard-admin
```

---

### 4.2 shill-guard-auth（认证授权服务）

**职责：**
- 用户注册（手机号/邮箱+密码，BCrypt加密）
- 用户登录，签发 JWT AccessToken + RefreshToken
- Token 刷新
- Token 注销（Redis黑名单）
- 验证 Token 有效性（供网关调用）
- 检查用户是否被禁言（禁言用户不允许发评论）

**主要接口：**
```
POST /api/auth/register      注册
POST /api/auth/login         登录
POST /api/auth/refresh       刷新Token
POST /api/auth/logout        注销
GET  /api/auth/validate      验证Token（内部接口，网关调用）
```

**Redis使用：**
- `token:black:{jti}` → Token黑名单
- `user:login:{userId}` → 登录状态缓存

---

### 4.3 shill-guard-user（用户服务）

**职责：**
- 用户个人信息查询/修改
- 头像上传（调用File服务）
- 关注/取关操作
- 查询粉丝列表/关注列表
- 用户禁言状态查询（供其他服务调用）
- 更新用户禁言状态（供Agent服务调用）

**主要接口：**
```
GET    /api/user/{userId}           查询用户信息
PUT    /api/user/profile            修改个人信息
POST   /api/user/avatar             上传头像
POST   /api/user/follow/{userId}    关注用户
DELETE /api/user/follow/{userId}    取关用户
GET    /api/user/followers          粉丝列表
GET    /api/user/following          关注列表
PUT    /api/user/status             更新禁言状态（内部接口）
```

**Redis使用：**
- `user:info:{userId}` → 用户信息缓存（5分钟）
- `user:muted:{userId}` → 禁言状态缓存

---

### 4.4 shill-guard-content（内容服务）

**职责：**
- 帖子/视频的发布、编辑、删除、查询
- 评论的发表、删除、查询（支持二级回复）
- 点赞/取消点赞（评论和帖子）
- 评论列表分页查询
- 热门内容推荐（按点赞/评论数排序）
- 发表评论前校验用户是否被禁言（调用User服务）

**主要接口：**
```
POST   /api/content/post            发布帖子
GET    /api/content/post/{postId}   帖子详情
GET    /api/content/post/list       帖子列表（分页）
DELETE /api/content/post/{postId}   删除帖子

POST   /api/content/comment         发表评论
GET    /api/content/comment/list    评论列表（分页）
DELETE /api/content/comment/{id}    删除评论

POST   /api/content/like            点赞
DELETE /api/content/like            取消点赞
```

**Redis使用：**
- `post:detail:{postId}` → 帖子详情缓存
- `post:like:count:{postId}` → 点赞数缓存（定期同步DB）
- `comment:like:count:{commentId}` → 评论点赞数缓存

---

### 4.5 shill-guard-report（举报服务）

**职责：**
- 用户提交举报
- 举报记录查询
- 举报处理状态更新（审核员操作，调用Admin服务）
- 举报提交后发送 RabbitMQ 消息，触发 Agent 分析

**主要接口：**
```
POST /api/report/submit             提交举报
GET  /api/report/my                 我的举报记录
GET  /api/report/{reportId}         举报详情
PUT  /api/report/handle             处理举报（内部/管理员接口）
```

**MQ消息：**
- 发送：`exchange.report → queue.agent.detect`（触发Agent对被举报用户检测）

---

### 4.6 shill-guard-agent（Agent调度服务）⭐核心

**职责：**
- 管理 Agent 定时检测任务配置（CRUD）
- 定时调度（基于 xxl-job 或 Spring Scheduler）
- 调用 Python Agent 服务的 REST API
- 接收 Python Agent 返回结果，写入 agent_detection_result
- 对确认违规用户执行禁言逻辑
- 生成并上传证据文件到 MinIO（调用File服务）
- 禁言后更新 sys_user.status（调用User服务）
- 禁言后触发发送通知（发送MQ消息）
- 消费举报队列消息，对单个用户触发检测

**主要接口：**
```
POST /api/agent/task/trigger        手动触发检测任务（管理员）
GET  /api/agent/task/list           检测任务列表
GET  /api/agent/task/{taskId}       任务详情
GET  /api/agent/result/list         检测结果列表
GET  /api/agent/result/{userId}     某用户最新检测结果
PUT  /api/agent/result/review       人工复审结果提交

GET  /api/agent/mute/list           禁言记录列表
GET  /api/agent/mute/{muteId}       禁言详情
POST /api/agent/mute/manual         手动禁言（管理员）
PUT  /api/agent/mute/revoke         撤销禁言
```

**调用 Python Agent 接口（HTTP）：**
```
POST http://python-agent:5000/api/detect
     Body: { userIds: [...], batchSize: 100 }
     Response: { results: [{userId, anomalyScore, shillProbability, evidence, violatedRules, violatedLaws}] }
```

**MQ消息：**
- 消费：`queue.agent.detect`（处理举报触发的检测）
- 发送：`exchange.mute → queue.notify.mute`（禁言后通知）

---

### 4.7 shill-guard-appeal（申诉服务）

**职责：**
- 被禁言用户提交申诉
- 查询申诉详情（含系统出示的证据快照）
- 管理员审核申诉（通过/驳回）
- 申诉通过后调用User服务解除禁言
- 申诉结果触发通知（发送MQ消息）

**主要接口：**
```
POST /api/appeal/submit             提交申诉
GET  /api/appeal/my                 我的申诉记录
GET  /api/appeal/{appealId}         申诉详情（含证据快照）
PUT  /api/appeal/review             审核申诉（管理员）
```

**MQ消息：**
- 发送：`exchange.appeal → queue.notify.appeal`（申诉结果通知）

---

### 4.8 shill-guard-notify（通知服务）

**职责：**
- 消费各服务发送的 MQ 消息，写入 sys_notification
- 查询用户未读通知
- 标记已读
- （可选）WebSocket 实时推送未读数角标

**消费的 MQ 队列：**
```
queue.notify.mute     → 禁言通知（发给被禁言用户）
queue.notify.appeal   → 申诉结果通知
queue.notify.report   → 举报处理结果通知
queue.notify.interact → 互动通知（评论/点赞，由Content服务发送）
```

**主要接口：**
```
GET  /api/notify/list              通知列表（分页）
GET  /api/notify/unread/count      未读数量
PUT  /api/notify/read/{noticeId}   标记已读
PUT  /api/notify/read/all          全部已读
```

---

### 4.9 shill-guard-file（文件服务）

**职责：**
- 封装 MinIO 操作，提供统一文件上传/下载接口
- 生成预签名访问 URL
- 存储类型区分：头像 / 帖子图片 / 证据文件 / 申诉截图

**主要接口：**
```
POST /api/file/upload              上传文件，返回访问URL
GET  /api/file/url/{fileKey}       获取预签名URL
DELETE /api/file/{fileKey}         删除文件（内部接口）
```

**MinIO Bucket 规划：**
```
shill-guard-avatar     → 用户头像
shill-guard-post       → 帖子图片/视频封面
shill-guard-evidence   → Agent生成的证据文件（PDF/TXT）
shill-guard-appeal     → 申诉附件
```

## 五、Python Agent 服务设计

> 此部分由你独立开发，Java 侧仅通过 HTTP 调用接口

### 5.1 对外暴露接口（供 Java Agent调度服务调用）

```
POST /api/detect
描述：批量检测用户水军可疑程度
请求体：
{
  "taskId": "任务ID",
  "users": [
    {
      "userId": "用户ID",
      "comments": ["评论1", "评论2", ...]
    }
  ]
}
响应体：
{
  "taskId": "任务ID",
  "results": [
    {
      "userId": "用户ID",
      "anomalyScore": 0.95,
      "shillProbability": 0.92,
      "evidenceSummary": "该用户在多个视频下集中发布相似负面评论...",
      "evidenceDetail": "完整证据文本...",
      "violatedRules": ["评论规范第3条"],
      "violatedLaws": ["网络安全法第47条"]
    }
  ]
}

POST /api/knowledge/sync
描述：同步知识库（Java侧知识库更新后通知Python重建RAG索引）
请求体：{ "kbIds": [1, 2, 3] }

GET  /api/health
描述：健康检查
```

### 5.2 Python Agent 内部架构

```
Python Agent 服务
├── 水军群组检测模块（你的核心算法）
│   ├── 输入：用户评论历史
│   └── 输出：anomaly_score（0~1）
│
├── RAG 分析模块
│   ├── 向量数据库（Milvus/ChromaDB）
│   ├── 知识库文档（平台规则/法律/网暴定义）
│   └── LLM（qwen/gpt-4o）
│       输入：高分用户评论 + 检索到的相关法规
│       输出：文本证据 + 违规条款列表
│
└── FastAPI/Flask 接口层
    └── 对外暴露 REST API
```

### 6.3 ⭐ Agent 调用页面（/admin/agent/console）

```
功能：
├── 手动触发一次 Agent 检测任务
├── 实时查看检测进度（WebSocket 或 轮询）
├── 查看每个用户的检测结果和证据文本
├── 对疑似用户执行"手动禁言"或"标记误判"
├── 配置定时任务（Cron表达式/阈值参数）
└── 查看 LLM 调用日志（token消耗/响应耗时）
```

## 七、服务间通信设计

### 7.1 同步调用（OpenFeign）

```
Gateway ──────→ Auth（验证Token）
Content ──────→ User（查询用户禁言状态）
Agent   ──────→ User（更新禁言状态）
Agent   ──────→ File（上传证据文件）
Appeal  ──────→ User（解除禁言）
Admin   ──────→ Agent/Appeal/Content（聚合操作）
```

### 7.2 异步消息（RabbitMQ）

```
Exchange                 Queue                    消费者
─────────────────────────────────────────────────────────
exchange.report    →  queue.agent.detect      → Agent服务
exchange.mute      →  queue.notify.mute       → Notify服务
exchange.appeal    →  queue.notify.appeal     → Notify服务
exchange.report    →  queue.notify.report     → Notify服务
exchange.interact  →  queue.notify.interact   → Notify服务
```

### 7.3 Redis 缓存策略

```
Key 规范                        TTL       用途
─────────────────────────────────────────────────────
token:black:{jti}              Token过期时间  JWT黑名单
user:info:{userId}             5min       用户信息缓存
user:muted:{userId}            10min      禁言状态缓存
post:detail:{postId}           3min       帖子详情缓存
post:like:count:{postId}       实时        点赞数缓存
comment:like:count:{commentId} 实时        评论点赞数缓存
agent:task:status:{taskId}     1h         任务执行状态
```

```
  → 前端完成 Agent控制台页面

阶段四（申诉与管理后台）
  → Appeal + Admin
  → 实现申诉流程 + 管理员审核
  → 前端完成管理后台所有页面
```
