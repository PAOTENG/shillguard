# 解析文档

## 概述

1. 支持格式：纯文本、MD、PDF、DOCX、PPT、XLSX、CSV
2. 匹配文档后缀，调用对应函数，并获得结果，进行校验

> **注意**：用户自己上传文件，需要先把文件读取为 byte 字节类型，然后执行统一的文件解析。
>

## 3. 公开接口 `parse_document`

- 需要文件路径、后缀、字符限制
- 通过后缀映射不同函数

## 不同类型解析思路

### 1. TXT / Markdown

直接解码：`data.decode()`，MD 文件同样直接解码。

---

### 2. PDF 格式

#### 三阶段解析

1. 针对文本格式，直接用 PyMuPDF 进行提取（文本原生 + 复杂版式/多栏/表格/跨页），内容会封装到多个 block，读取时遍历 block 列表。
2. 根据读取结果，判断 PDF 类型：文本为主 / 扫描件 / 复杂型。
3. 如果是扫描件，则使用 OCR 识别。

#### 详细分类

##### 2.1 文本为主的 PDF

使用 PyMuPDF（`fitz`）将字节数据打开为 PDF 文档对象，逐页读取。

**每页处理流程：**

1. 获取该页所有 block，按坐标值重新排序（防止多栏乱序）
2. 每个 block 是一个元组，固定结构：
   - `b[0]`, `b[1]` → x, y 坐标
   - `b[4]` → 文字内容
3. 读取所有 block 的 `b[4]`，按顺序保存全文

##### 2.2 扫描件（OCR）

- 使用 `pdf2image.convert_from_bytes(data)` 将 PDF 转换为图片
- 使用 EasyOCR 的 `Reader.readtext()` 读取图片
- 注意：图片需先转换为 `np.array` 格式才能输入 EasyOCR
- 每个 result 包含置信度和识别内容，保留置信度高的内容，按顺序存储

### 3. DOCX 文档

**常用对象属性：**

| 对象 | 属性 | 说明 |
|------|------|------|
| `Document` | `.paragraphs` | 所有段落列表（按文档顺序）|
| `Document` | `.tables` | 所有表格列表 |
| `Document` | `.sections` | 节列表（含页眉/页脚/页边距设置）|
| `Document` | `.styles` | 样式字典（Heading 1/Normal 等）|
| `Document` | `.core_properties` | 元数据（作者/创建时间/标题）|
| `Paragraph` | `.text` | 段落纯文本（合并所有 run）|
| `Paragraph` | `.style.name` | 样式名，如 `Heading 1` / `Normal` |
| `Paragraph` | `.runs` | 格式片段列表（粗体/斜体会分段）|
| `Table` | `.rows` | 行列表 |
| `Row` | `.cells` | 单元格列表 |
| `Cell` | `.text` | 单元格纯文本 |

**已知局限：**
`doc.paragraphs` 和 `doc.tables` 是两个独立列表，无法保留段落与表格在文档中原始穿插顺序。对 RAG 语义检索场景影响不大，如需精确顺序可用 `doc.element` 遍历 XML。

**具体流程：**

```
Document.paragraphs → 遍历所有段落 → 保存 paragraph.text
Document.tables → 遍历所有表格 → rows → cells → 保存 cell.text
```

### 4. PPTX 文档

**常用对象属性：**

| 对象 | 属性 | 说明 |
|------|------|------|
| `Presentation` | `.slides` | 幻灯片列表 |
| `Presentation` | `.slide_width/height` | 幻灯片尺寸（EMU 单位）|
| `Slide` | `.shapes` | 所有形状列表 |
| `Slide` | `.slide_layout` | 当前版式 |
| `Slide` | `.notes_slide` | 备注页 |
| `Shape` | `.has_text_frame` | bool，是否包含文本 |
| `Shape` | `.has_table` | bool，是否是表格 |
| `Shape` | `.has_chart` | bool，是否是图表 |
| `Shape` | `.shape_type` | 枚举值（文本框/图片/形状等）|
| `Shape` | `.text_frame.paragraphs` | 文本框中的段落列表 |

**已知局限：**
- SmartArt 内部文字无法直接提取（需解析 XML）
- 图片内文字需 OCR（本函数不处理）

**具体流程：**

```
PPT 文本：Presentation.slides → shapes → text_frame.paragraphs → runs → text
PPT 表格：shape.table → rows → cells → text
```

### 5. XLSX 文档

**`openpyxl.load_workbook()` 关键参数：**

| 参数 | 说明 |
|------|------|
| `read_only=True` | 只读模式，跳过样式/公式计算，内存占用减少约 60% |
| `data_only=True` | 返回单元格计算结果值（如 `150`），而非公式字符串（如 `=SUM(A1:A3)`）|

**常用对象属性：**

| 对象 | 属性 | 说明 |
|------|------|------|
| `Workbook` | `.sheetnames` | 所有工作表名称列表，如 `['Sheet1', '汇总']` |
| `Workbook` | `[sheet_name]` | 按名称获取工作表 |
| `Workbook` | `.active` | 活动工作表 |
| `Worksheet` | `.iter_rows(values_only=True)` | 逐行迭代，每行返回值元组 |
| `Worksheet` | `.max_row / .max_column` | 有数据的最大行/列号 |
| `Worksheet` | `.cell(row=1, column=1).value` | 指定单元格的值 |
| `Worksheet` | `.dimensions` | 数据范围字符串，如 `A1:H100` |

**具体流程：**

```
wb.sheetnames → 遍历所有工作表名称
  → wb[sheet_name] 获取工作表对象
  → ws.iter_rows() 遍历每行
  → 逐个 cell 进行 str() 转换（类型不统一：int/float/None/datetime 等）
  → 跳过全空行
  → 拼接并保存每行内容
```

> **注意**：与 CSV 不同，XLSX 每个 cell 的数据类型不统一，必须逐个 `str()` 转换后再拼接，不能直接 `join`。

### 6. CSV 文档

**csv 模块常用功能（Python 内置，无需安装）：**

| 函数/类 | 说明 |
|---------|------|
| `csv.reader(f)` | 迭代器，每次返回一行的列表 ← 本函数使用 |
| `csv.writer(f)` | 写入器，`writerow([...])` 写一行 |
| `csv.DictReader(f)` | 以首行为键，每行返回字典（适合有表头的 CSV）|
| `csv.DictWriter(f, fieldnames)` | 按字典写入 |

**关键细节：**
- `io.StringIO(text)`：将字符串包装成文件对象，供 `csv.reader` 按行迭代（直接传 `str` 会逐字符迭代，导致解析混乱）
- 全空行处理：`any(cell.strip() for cell in row)` 跳过空行

**具体流程：**

```
data.decode() → 文字字符串
  → io.StringIO(text) 包装成文件对象
  → csv.reader 解析（自动处理逗号/引号/换行转义规则）
  → 遍历每行 row（已是 str 列表，可直接拼接）
  → 跳过全空行
  → 保存行内容
```

> **与 XLSX 对比**：CSV 中每个 cell 经 `csv.reader` 处理后已统一为 `str`，可直接 `" | ".join(row)`；XLSX 需逐个转换类型后再拼接。
