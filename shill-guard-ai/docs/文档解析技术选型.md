# 文档解析技术选型详解

> 本文档说明 `parse_doc.py` / `app/rag/doc_parser.py` 中各格式所使用的解析技术、
> 备选方案及各方案横向对比，供开发参考。

## 二、TXT / Markdown 解析

### 使用技术
`bytes.decode(encoding)`：Python 内置方法，按指定编码将字节翻译成 Unicode 字符串。

### 编码尝试顺序
```
utf-8 → gbk → latin-1 → utf-8(errors="replace")
```

| 编码 | 覆盖场景 | 特点 |
|------|----------|------|
| UTF-8 | macOS / Linux / 网络文件 / 新版 Windows | 现代标准，优先尝试 |
| GBK | 旧版 Windows 中文文件、旧版 Word 导出 | 中文 Windows 默认编码 |
| Latin-1 | 西欧文件 | 任意单字节均合法，不会抛异常，作倒数第二保险 |
| UTF-8 + replace | 极端情况兜底 | 用 `?`（U+FFFD）替换无法解码的字节，保证不崩溃 |

### 为什么 Markdown 不渲染成 HTML 再剥标签？
LLM 天然理解 `#`、`**`、\` 等 Markdown 语法，保留原始格式反而保留了标题层级、
代码块等语义结构，渲染成 HTML 反而会丢失这些信息。

## 三、PDF 解析（三阶段策略）

### 阶段1：PyMuPDF 文字提取

**使用库**：`PyMuPDF`（import 时叫 `fitz`）

**原理**：PDF 内部以矢量方式存储文字（字符编码 + 坐标），PyMuPDF 直接读取
这些结构化数据，速度极快，不涉及图像渲染。

**核心方法**：`page.get_text("blocks")` 返回文字块列表，每块包含：
```
(x0, y0, x1, y1, text, block_no, block_type)
 左上角   右下角  文字   块编号    类型(0=文字/1=图片)
```

**排序重建阅读顺序**：
```python
blocks.sort(key=lambda b: (round(b[1] / 12), b[0]))
# 先按 y 坐标（粗粒化，容忍同行内 ±6pt 偏差）→ 再按 x 坐标
# 效果：正确处理双栏 PDF，不会左右栏文字交叉混排
```

### 阶段2：扫描件检测

```python
len(text.replace("\n","").replace(" ","").strip()) < 80
# 有效字符 < 80 → 判定为扫描件 → 触发阶段3
```

扫描件 PDF 的内容全是图片，PyMuPDF 无法提取文字，有效字符极少。

### 阶段3：EasyOCR 扫描件识别

**使用库**：`EasyOCR` + `pdf2image`

**流程**：
```
PDF bytes
  ↓ pdf2image（调用 poppler 渲染）
PIL Image 列表（每页一张，dpi=300）
  ↓ np.array()
numpy 数组（高×宽×3 的 RGB 像素矩阵）
  ↓ easyocr.Reader.readtext()
[[坐标框, "识别文字", 置信度], ...]
  ↓ 过滤置信度 < 0.3
纯文字字符串
```

## 四、PDF 解析技术横向对比

| 库 | 原理 | 文字PDF | 扫描件 | 复杂版式 | 中文 | GPU | 速度 | 费用 |
|----|------|---------|--------|----------|------|-----|------|------|
| **PyMuPDF** | 读取 PDF 矢量结构 | ✅ 极佳 | ❌ | ✅ 良好（block排序） | ✅ | ❌ | 极快 | 免费 |
| PyPDF2 | 读取 PDF 文字层 | ✅ 一般 | ❌ | ❌ 容易乱序 | ⚠️ | ❌ | 快 | 免费 |
| pdfplumber | 读取 PDF 文字层 | ✅ 良好 | ❌ | ✅ 表格提取好 | ✅ | ❌ | 中等 | 免费 |
| Unstructured | 多策略自动选择 | ✅ | ✅ | ✅ 极佳 | ✅ | 可选 | 慢 | 免费（本地）|
| LlamaParse | 云端 LLM 解析 | ✅ | ✅ | ✅ 极佳 | ✅ | 云端 | 慢 | **付费** |
| **EasyOCR** | 深度学习 OCR | ❌（用于扫描件）| ✅ 极佳 | ✅ | ✅ ~95% | ✅ | 中等（GPU快）| 免费 |
| Tesseract | 传统图像处理 OCR | ❌ | ✅ 一般 | ⚠️ | ⚠️ ~83% | ❌ | 慢 | 免费 |
| PaddleOCR | 深度学习 OCR | ❌ | ✅ 极佳 | ✅ | ✅ ~96% | ✅ | 快 | 免费 |

> **当前方案**：PyMuPDF（文字PDF）+ EasyOCR（扫描件），覆盖 90% 以上场景，
> 完全免费，无系统级 OCR 引擎依赖（仅需 poppler）。

## 五、OCR 引擎横向对比

| 引擎 | 架构 | 中文准确率 | GPU支持 | 安装复杂度 | 系统依赖 | 适用场景 |
|------|------|-----------|---------|-----------|---------|---------|
| **EasyOCR** ← 当前 | CRNN + Transformer | ~93~96% | ✅ PyTorch | pip 一行 | 无 | 通用，中英混排 |
| Tesseract | 传统图像处理 | ~80~85% | ❌ | 需系统安装 | 需安装二进制 | 简单英文文档 |
| PaddleOCR | PP-OCR（百度） | ~95~97% | ✅ PaddlePaddle | pip 安装 | 无 | 中文场景最佳，但与新版 protobuf 冲突 |
| TrOCR（微软）| Transformer | ~94% | ✅ PyTorch | pip 安装 | 无 | 手写体识别好 |
| Surya | Transformer | ~95% | ✅ PyTorch | pip 安装 | 无 | 多语言，新兴 |

> **为何不用 PaddleOCR**：PaddlePaddle 2.x 硬要求 `protobuf<=3.20`，
> 而 LangGraph 要求 `protobuf>=6.32`，两者在同一 Python 环境中**完全不兼容**。

## 六、DOCX 解析

### 使用技术：python-docx

**原理**：DOCX 本质是 ZIP 压缩包，内含 XML 文件。python-docx 解析 XML 结构，
提取段落和表格数据。

**关键对象**：
```
Document
  ├── .paragraphs   → 段落列表，每个段落含 .text 属性
  └── .tables       → 表格列表
        └── .rows → 行列表
              └── .cells → 单元格列表，每个含 .text
```

**备选方案对比**：

| 库 | 特点 | 缺点 |
|----|------|------|
| **python-docx** ← 当前 | 轻量，精确提取段落和表格 | 不处理页眉页脚（默认） |
| docx2txt | 更简单，一行代码 | 只取纯文字，表格结构丢失 |
| mammoth | 可转 HTML / Markdown | 依赖较多 |
| Unstructured | 自动识别所有元素 | 重，安装复杂 |

## 七、PPTX 解析

### 使用技术：python-pptx

**原理**：PPTX 同样是 ZIP+XML，python-pptx 遍历每张幻灯片的所有"形状"
（Shape），从文字框（TextFrame）中提取文字。

**关键层级**：
```
Presentation
  └── .slides（幻灯片集合）
        └── Slide（单张幻灯片）
              └── .shapes（所有形状）
                    └── Shape（文字框/图片/表格等）
                          └── .text_frame.text  ← 提取文字
```

**备选方案**：
- `python-pptx`：唯一主流选择，无竞争者

## 八、XLSX 解析

### 使用技术：openpyxl

**关键参数**：
```python
openpyxl.load_workbook(file, read_only=True, data_only=True)
# read_only=True  → 只读模式，跳过样式/条件格式计算，内存占用减少约 60%
# data_only=True  → 返回单元格计算结果值，而非公式字符串
#                   例：=SUM(A1:A3) → 150（结果）而非 "=SUM(A1:A3)"
```

**备选方案对比**：

| 库 | 特点 | 缺点 |
|----|------|------|
| **openpyxl** ← 当前 | 纯 Python，支持 .xlsx | 不支持 .xls（旧格式） |
| xlrd | 支持 .xls 旧格式 | 新版已不支持 .xlsx |
| pandas | `read_excel()` 一行搞定 | 依赖重（numpy+pandas），适合数据分析 |
| xlwings | 可调用 Excel 应用程序 | 需安装 Excel，仅 Windows/macOS |

## 九、CSV 解析

### 使用技术：Python 内置 `csv` 模块

**特点**：无需安装，处理逗号分隔、引号包裹、换行转义等 CSV 格式规则。

**关键细节**：
```python
# csv.reader 需要"按行迭代"的对象，不能直接传 str
# str 迭代是逐字符的，io.StringIO 迭代是逐行的

csv.reader(io.StringIO(text))    # ✅ 逐行
csv.reader(text.splitlines())    # ✅ 也可以
csv.reader(text)                 # ❌ 逐字符，完全乱掉
```

**备选方案**：
- `pandas.read_csv()`：功能更强，但依赖重，本项目仅需文字提取，内置模块够用

## 十、整体数据流

```
用户上传文件（任意格式）
  ↓ 浏览器 HTTP multipart 传输
FastAPI UploadFile
  ↓ await file.read()
bytes（原始字节，与磁盘文件完全一致）
  ↓ 根据文件后缀名分发
  ├── .txt / .md  → decode() → str
  ├── .pdf        → PyMuPDF → str（或 EasyOCR → str）
  ├── .docx       → python-docx → str
  ├── .pptx       → python-pptx → str
  ├── .xlsx       → openpyxl → str
  └── .csv        → decode() + csv.reader → str
          ↓
      纯文本 str（统一格式）
          ↓
      Embedding 模型（OpenAI / 本地模型）
          ↓
      向量 list[float]
          ↓
      向量数据库存储 / 相似度检索
```
